# appstorespy-api-docs

## Mission

appstorespy-api-docs keeps the README, the Postman collection and the runnable examples in step with the live contract of api.appstorespy.com (its OpenAPI), so a developer or an AI agent makes a first successful call without writing to support. Its goals serve the goals of AppStoreSpy as a whole, in AppstorespyOS `docs/product.md`

## Users

- U-1: Customers' developers and data teams who integrate the REST API
- U-2: AI agents, and the people who build them, that connect to the MCP server and read the README as their instructions
- U-3: API directories such as apis.io, which index and score this repository
- U-4: AppStoreSpy's agents (as-rest and others), which document every API change here

## Goals

- G-1: Every field and endpoint that ships in as-rest is documented in the README and the Postman collection within a week of its deploy
- G-2: The Postman collection is always generated by `tools/generate_postman.py` from the current `openapi.json`, never edited by hand
- G-3: The examples in `examples/` run against the production API and are checked in CI
- G-4: A high score in API directories such as apis.io

## Non-goals

- N-1: The API contract and its reference: they live in as-rest (`openapi.json`, `/docs`), and this repository neither edits nor duplicates them

## Quality bar

- Q-1: Only what already works on api.appstorespy.com is documented, with a request example that was checked
- Q-2: Examples use `YOUR_KEY` only; keys and credentials never enter this public repository
- Q-3: No unverified figures or promises: a number such as the count of apps carries its date and source
